## 💡 Зачем нужен AnD os?

Современные автономные кодинг-агенты (Claude Code, OpenCode, Gemini CLI, Cursor, ChatGPT) на реальных проектах сталкиваются с четырьмя системными проблемами:

1. **Раздувание контекста и потеря памяти (Context Bloat):** Загрузка тысяч строк логов и сырых файлов деградирует качество модели уже через 8–15 шагов диалога.
2. **Галлюцинации успеха (Hallucinated Execution):** Агент рапортует «Всё готово и работает!», даже не запуская компилятор или игнорируя ненулевой код возврата.
3. **«Костыли» и маскировка ошибок (Band-Aid Swallowing):** Агенты обожают писать блоки `try: ... except: pass`, которые скрывают сломанные зависимости и тихие баги.
4. **Хаос инструментов (Tool Sprawl):** Десятки несогласованных скриптов борются за приоритет вызова, расходуя контекстное окно.

**AnD os** решает это, выстраивая **детерминированный слой микроядра** между ИИ-агентом и вашей файловой системой.

```

┌────────────────────────────────────────────────────────┐
│                   Микроядро AnD os                     │

│  • 9-фазный шлюз верификации Quick Verify (<1.5с)      │
│  • Двухскоростное управление (Fast-Track / Защита баз) │
│  • Декларативный ABI навыков v2.1 + SOS мульти-ядро    │
│  • Замкнутый цикл эмпирической памяти (Learn Loop)     │
│  • Парадигма Think in Code (сжатие вывода до 98.8%)    │
└───────────────────────────┬────────────────────────────┘
```

## 🏛️ Ключевые архитектурные принципы

### 1. 9-фазный цикл предварительной проверки (`quick_verify.py`)
Ни одна задача не считается выполненной, пока не пройден локальный субсекундный шлюз качества:
- **Фаза 0:** Паритет среды и тулчейна (строго Python 3.12 LTS).
- **Фаза 1:** Парсинг синтаксического дерева AST.
- **Фаза 2:** Семантический линтинг типов и неиспользуемых переменных.
- **Фаза 3:** Clean Code Guard (запрет голых `except` и тихого проглатывания ошибок).
- **Фаза 4:** Таргетированные регрессионные юнит-тесты.
- **Фаза 5:** Сканер утечек секретов и API-ключей.
- **Фаза 6:** Анализ диффа и дельты изменений.
- **Фаза 7:** Проверка целостности графа базы знаний (пропускается в автономном репозитории).
- **Фаза 8:** Актуальность скомпилированного индекса правил.

### 2. Декларативный стандарт навыков ABI v2.1
Скиллы — это не просто случайные скрипты, а изолированные декларативные модули:
- Машинно-читаемый манифест (`name`, `domain`, `lifecycle`, `probe_cmd`).
- Герметичные канареечные проверки (`probe_cmd`), исполняемые за $<500$ мс.
- Мгновенный параллельный аудит всех скиллов через **SOS Multi-Core Auditor** ($\le 300$ мс).

### 3. Парадигма «Think in Code»
Вместо чтения гигабайтов сырых файлов в окно контекста агент генерирует однострочные детерминированные Python-фильтры, сжимая передаваемый в модель контекст на **98.8%**.

## 🛠️ Установка и требования

AnD os Core поставляется с **нулевыми внешними зависимостями**: не требуется `pip install`, нет внешних сетевых сервисов или раздутых фреймворков.

| Требование | Минимум | Примечание |
| :--- | :--- | :--- |
| Python | 3.10+ (рекомендуется 3.12 LTS) | Только стандартная библиотека (`dependencies = []`) |
| Git | 2.x | Клонирование и версионирование |
| ОС | macOS / Linux | Оптимизировано под Apple Silicon и Linux |

```bash
git clone https://github.com/KornAnd/and-os-core.git
cd and-os-core

# Мгновенная самопроверка ядра:
python3 and_os/bin/quick_verify.py
```

## 🔌 Пошаговое подключение любых ИИ-агентов

AnD os подключается к любому агенту через **два легковесных файла и один CLI-фасад** без запуска тяжелых фоновых демонов.

### Универсальная точка входа (`AGENTS.md`)
Поместите файл `AGENTS.md` в корень вашего рабочего репозитория:
```markdown
# AGENTS.md — Стандарт дисциплины агента
1. Ознакомься с `and_os/etc/rules_fast_index.json` (<450 токенов: ключевые инварианты).
2. Перед правками кода: запусти `python3 and_os/bin/quick_verify.py` для оценки текущей базы.
3. Правило чистоты: запрещены голые блоки `except: pass` и субъективные допущения.
4. После любых изменений: запусти `python3 and_os/bin/quick_verify.py`. Запрещено рапортовать об успехе, пока все фазы не будут ЗЕЛЕНЫМИ (Exit code 0).
```

### Рецепты интеграции под конкретные среды:

#### 🟣 1. Claude Code
Создайте `CLAUDE.md` в корне репозитория:
```markdown
# CLAUDE.md
- Правила: Читай и соблюдай `and_os/etc/rules_fast_index.json`.
- Проверка: Всегда запускай `python3 and_os/bin/quick_verify.py`.
- Критерий готовности: Задача выполнена ТОЛЬКО если quick_verify завершился с кодом 0.
```

#### 🟢 2. OpenCode
Настройте файл `opencode.json` в корне проекта:
```json
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "and_os/etc/rules_fast_index.json"
  ],
  "permission": {
    "skill": {
      "*": "allow"
    }
  }
}
```

#### 🔵 3. Gemini CLI / Antigravity
Создайте симлинк `GEMINI.md` на общий манифест:
```bash
ln -s AGENTS.md GEMINI.md
```
Или укажите правила в конфигурации `.gemini/config.json`.

#### 🟠 4. ChatGPT / OpenAI Codex / Custom GPTs
Добавьте в системные инструкции (Custom Instructions / System Prompt):
```text
Ты работаешь под управлением детерминированного микроядра AnD os.
При старте сессии прочитай `and_os/etc/rules_fast_index.json`.
Никогда не маскируй исключения (no bare except). Перед завершением задачи выполни:
`python3 and_os/bin/quick_verify.py` и убедись, что все фазы пройдены успешно.
```

#### 🟡 5. Cursor / Windsurf
Создайте `.cursorrules` в корне вашего проекта:
```text
Всегда читай и следуй правилам из and_os/etc/rules_fast_index.json.
Перед тем как объявить задачу завершенной, обязательно запусти:
python3 and_os/bin/quick_verify.py
Если обнаружены ошибки (exit code != 0), устрани причину в коде. Не глуши ошибки.
```

## 🧩 Встроенная библиотека инженерных навыков (12 эталонных системных модулей)

В состав ядра входят проверенные системные навыки в каталоге `and_os/lib/skills/`:
- **`system-architect` (v1.2):** Предпроектный допрос (Phase -1 Grilling/Interview из 6 калибрующих вопросов), Spec-Before-Code, C4/ADR-проектирование.
- **`task-graph` (v1.3):** Вертикальная нарезка задач на атомарные тикеты (*tracer-bullet*) с защитой от гонок файлов `MUTUAL_EXCLUSION_REQUIRED`.
- **`dev-flow` (v2.0):** TDD Iron Law, поиск швов (*seams*), Red-Loop-First отладка + инженерный стандарт чистого кода Uncle Bob.
- **`system-audit` (v2.0):** 8-кольцевой Health Grid ядра, 4-вопросный Test Value Bar, карточки списания тестов + аудит безопасности (OWASP/STRIDE).
- **`file-lifecycle` (v2.0):** Полный жизненный цикл заметок: M1 интеллектуальная маршрутизация + M2 синхронизация CONTEXT.md.
- **`memory` (v2.0):** Замкнутый контур памяти: M1 recall ловушек, M2 learn решений, M3 аудит базы + M4 архитектурные решения (ADR).
- **`skill-creator` (v1.2):** Создание и линтинг навыков по ABI v2.1, A/B тестирование триггеров и диета промптов.
- **`skill-router` (v1.0):** Арбитраж намерений пользователя и выбор строго одного первичного навыка (Правило №12).
- **`context-compressor` (v1.0):** Упаковка контекста кодобаз и директорий с ограничением потока (<100 токенов на вызов).
- **`github-ops` (v1.3):** Токеноэффективная работа через официальный GitHub CLI + протокол безопасного экспорта Zero-Leak.
- **`obsidian-bases` (v1.0):** Декларативные, реактивные таблицы `.base` и формулы без тяжелых JS-плагинов.
- **`temporal-consistency-guard` (v1.1):** Контроль дефликеринга видео/анимации и детерминированные рендер-контракты (`hyperframes-contract`).

## 🔒 Стандарт безопасности Air-Gap (Правила №57 и №58)

AnD os изначально спроектирован с физической изоляцией данных:
- Системный код ядра открыт и живет в `and_os/`.
- Корпоративные и персональные базы знаний строго изолированы и защищены AST-шлюзом.
- В микроядре отсутствуют скрытые телеметрические трекеры или неконтролируемые сетевые запросы.
